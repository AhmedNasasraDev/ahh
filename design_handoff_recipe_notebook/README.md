# Handoff: מחברת מתכונים מקצועית — Recipe Notebook

## Overview

אפליקציית מחברת מתכונים ל־iOS, בעברית RTL מלאה, mobile-first. מיועדת לקהל רחב — משתמש ביתי, טבח, קונדיטור, אופה, בריסטה, ברמן, תלמיד, מדריך ובית ספר — ומשתמשת ב־Progressive Disclosure: פרופיל המשתמש (ביתי / מקצועי / לימוד) והעדפות המדידה קובעים מה נחשף קודם, בלי לנעול שום כלי.

מעל העיצוב יש מנוע חישוב אמיתי ועובד: המרות יחידות תלויות חומר גלם, תשואה ופחת, עלויות ופוד קוסט, הידרציה נטו, טמפרטורת מים, תת־מתכונים רקורסיביים.

**המסמך המרכזי להטמעה הוא \`RECIPE_NOTEBOOK_IMPLEMENTATION_SPEC.md\` (599+ שורות).** הוא מתעד את כל הפיצ'רים, ה־user flows, הוולידציות, התפקידים, ההרשאות, מודל הפרטיות, לוגיקת ההמרה, ה־edge cases וה־acceptance criteria — ואת כל מה שמסומן \`REQUIRES BACKEND\`. ה־README הזה הוא המבוא; המפרט הוא האמת.

## About the Design Files

הקבצים בחבילה הזאת הם **מסמכי עיצוב שנכתבו ב־HTML** — פרוטוטייפ שמראה את המראה וההתנהגות המיועדים, לא קוד production להעתקה ישירה.

המשימה היא **לשחזר את העיצובים האלה בסביבה הקיימת של אפליקציית היעד** (React Native, SwiftUI, React, וכו') לפי התבניות והספריות שכבר נהוגות בה. אם עוד אין סביבה — לבחור את המתאימה ולממש שם.

חריג אחד חשוב: **\`engine.js\`, \`measure.js\`, \`parser.js\` ו־\`groups.js\` הם לוגיקה עסקית אמיתית, לא עיצוב.** טבלאות הצפיפות, הגרמים־לכוס פר חומר גלם, אחוזי המים, חישובי העלות והתשואה, וכללי ההרשאות — אלה הערכים שצריכים לעבור לקוד היעד כמו שהם. אל תמציא אותם מחדש.

## Fidelity

**High-fidelity.** צבעים, טיפוגרפיה, מרווחים ומצבי אינטראקציה סופיים. יש לשחזר את ה־UI במדויק בספריות של הקודבייס.

## Interactions & Behavior

העיקרון החוזר בכל המוצר: **חישוב אינו עריכה.** סקיילינג, המרת יחידות, התאמת גודל תבנית והצגה בגרמים/ביתי — כולם מציגים תוצאה מחושבת ולא דורסים את המתכון המקורי. המשתמש בוחר במפורש אם לשמור את התוצאה כגרסה.

- **המרת יחידה פר־רכיב:** מציגה כמות מקורית, יחידה מקורית, גודל כלי המדידה, יחידת היעד, התוצאה, ומקור הנתון — מדויק / משוער / כיול אישי. אם אין נתון אמין, לא מוצג מספר.
- **כיול אישי:** "אצלי כוס מהקמח הזה = 132 גרם". דורס נתון מערכת, מסומן תמיד בבירור.
- **סקיילינג:** לפי מנות / יחידות / משקל סופי / נפח סופי / מלאי קיים.
- **פרטיות בקבוצות:** מחברת אישית פרטית כברירת מחדל. תלמיד אינו רואה מחברות של אחרים. מדריך אינו רואה את המחברת האישית של התלמיד. הערות אישיות אינן מוצגות לאף אחד. ה־UI משקף את המודל הזה גם כשהנתונים Demo.
- **HACCP:** סטטוס האצווה נגזר ולא מאוחסן — אי אפשר לסמן אצווה כתקינה בלי התיעוד. מדידת קירור מעל 5°C מייצרת חריגה גם אם כל הסימונים מסומנים.

## State Management

כל ה־state נשמר במפתח אחד דרך \`window.storage\` כ־JSON (לא localStorage). מכיל: מתכונים, חומרי גלם ומחירים, העדפות מדידה, כלי מדידה, כיול, פרופיל, אצוות, קבוצות, קורסים, הרשאות, הערות אישיות, גרסאות.

בקוד היעד זה צריך להתפצל לטבלאות אמיתיות — ראו \`Database requirements\` במפרט.

## מה אמיתי ומה Demo

**אמיתי ועובד:** כל מנוע החישוב, ההמרות, העלויות, התשואה, ההידרציה, הפרסינג, הטיימרים, הסקיילינג, נגזרות ה־HACCP.

**Demo / UI בלבד — \`REQUIRES BACKEND\`:** authentication · חברות בקבוצות והזמנות · קוד/קישור פרטי · הרשאות פר־מתכון ואכיפתן · RLS על מחברות אישיות · סנכרון גרסאות · שיתוף חוץ־קבוצתי · מסד צפיפויות משותף · כיול פר־חשבון · העלאת צילומי אצווה + חותמת זמן מאומתת שרת · נקודות בקרה פר־מטבח.

הרשימה המלאה, כולל דרישות Auth, Storage, Security ו־RLS, נמצאת במפרט.
